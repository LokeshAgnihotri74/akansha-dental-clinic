📅 Workflow 1: Public Online Appointment Booking Flow

● END-TO-END PATIENT WORKFLOW
1

Default Selections

UI sets Doctor = "Any Available Doctor" (₹0 fee) & Treatment = "General Checkup" (₹399).

2

Dynamic Slot Fetch

Calls /available-slots. Engine excludes booked slots & filters past same-day hours.

3

10-Digit Phone Check

Validates 10-digit Indian format (/^[6-9]\d{9}$/). Rejects invalid contact entries.

4

Patient Record Match

Looks up phone in patients table. If found reuses patient ID; if new, registers record.

5

Atomic Slot Lock

Inserts appointment with status PENDING and auto-generates APT-2026-XXXX.

6

Audit & Response

Logs to appointment_status_history and returns HTTP 201 with confirmation summary.

🔒 Workflow 2: Clinical Admin JWT Authentication & Status Workflow

● RBAC PROTOCOL
A

1-Click Credentials

Admin enters credentials or clicks demo pills (Super Admin / Staff Desk).

B

BCrypt Verification

Backend compares plain password against salted BCrypt hash in admins table.

C

JWT Token Generation

Signs token with claims { id, username, role }; expires in 24 hours.

D

Protected Desk Action

Doctor clicks "Confirm". JWT filter verifies Bearer header & populates req.user.

E

Status Transition

Transitions PENDING → CONFIRMED → COMPLETED / CANCELLED.

F

Live Dashboard Sync

Dashboard aggregates total OPD flow, revenue collected, and today's queue.

MySQL 8.x Normalized Data Schema

akansha_dental_db (10 Relational Tables)

Full ACID transactions, foreign key cascades, and unique composite slot constraints.

appointments Core
  • PK id (BIGINT)
  • UK booking_reference
  • FK patient_id → patients
  • FK doctor_id (0=Any)
  • FK service_id → services
  • appointment_date, time_slot
  • status (PENDING/CONFIRMED)
  • total_price (DECIMAL 10,2)
patients Directory
  • PK id (BIGINT)
  • full_name (VARCHAR 150)
  • UK phone (10 Digits)
  • email, blood_group
  • medical_history (TEXT)
  • created_at (TIMESTAMP)
doctors Roster
  • PK id (BIGINT)
  • name, qualification
  • specialization
  • consultation_fee
  • is_active (BOOLEAN)
services Catalog
  • PK id (BIGINT)
  • name (General Checkup: 100)
  • category, base_price (₹399)
  • duration_minutes (30)
  • is_active (BOOLEAN)
admins Security
  • PK id (BIGINT)
  • UK username, email
  • password_hash (BCrypt)
  • role (SUPER_ADMIN/STAFF)
  • is_active (BOOLEAN)
status_history Audit
  • PK id (BIGINT)
  • FK appointment_id
  • old_status, new_status
  • changed_by, changed_at
  • notes (VARCHAR 255)
🛡️ Double-Booking Guard: Composite unique constraint on (doctor_id, appointment_date, time_slot, is_active) prevents race conditions under high traffic.
